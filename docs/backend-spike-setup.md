# Backend compatibility spike setup

This adds Payload 3.89.0 admin/API routes and a separate worker process. It does not yet implement questionnaires in the database, Gemini, Resend, or leads. The frontend remains the existing prototype.

Public routes now live under `app/(frontend)`; the URLs are unchanged. Payload has its own root layout under `app/(payload)`, so marketing styles/header/footer do not wrap the admin. Keep editing `app/globals.css` and the existing components as before.

## Environment

Install the locked dependencies with `npm.cmd ci`. The repository includes `compose.yaml` for a disposable PostgreSQL 16 database. Its port is bound only to `127.0.0.1:55432`; it is not exposed to the LAN. The generated `.env.development.local` is ignored by Git and contains the local database, Payload, and bootstrap credentials. Do not commit, copy into a deployment environment, or reuse those credentials.

The prerequisite is Docker Desktop (or another Docker Engine) with the Compose v2 plugin running and available as `docker`. Start the disposable database and wait for its health check:

```powershell
docker compose --env-file .env.development.local -f compose.yaml -f compose.dev.yaml up --detach --wait postgres
```

Run the local CLI commands below with `NODE_ENV=development`, which makes their `@next/env` loader use `.env.development.local` just like `next dev` does:

```powershell
$env:NODE_ENV='development'
```

`DATABASE_URL` must point only to the Compose database. `PAYLOAD_SECRET` must remain private and stable across the web and worker processes.

For this spike only, use `PAYLOAD_SCHEMA_PUSH=true` while initializing the disposable development database. The adapter explicitly disables schema push in production. Production migrations are a later backend task; do not point this spike's schema-push mode at existing valuable data.

CLI scripts load the same Next.js environment-file precedence as the web application. They do not print environment values.

## Admin

Set `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` (at least 16 characters), then run:

```powershell
npm.cmd run admin:bootstrap
npm.cmd run dev
```

Open `/admin` and log in. Remove the bootstrap environment variables afterward. The command refuses to overwrite an existing admin. Anonymous collection creation and the first-user endpoint are blocked by a server-side hook; creating the first admin requires the local command. This command is for a controlled single-operator bootstrap, not concurrent production provisioning.

## Durable job check

With schema initialized, set `PAYLOAD_SCHEMA_PUSH=false` in `.env.development.local` before starting multiple processes, then restart each CLI process. Do not enable schema push against an existing or valuable database.

```powershell
npm.cmd run job:fixture -- queue
```

Record the printed job ID and marker, then let the queue command exit. In a **new process**, run:

```powershell
npm.cmd run worker:once
```

After that worker exits, inspect from a **third process**:

```powershell
npm.cmd run job:fixture -- inspect 1
```

Replace `1` with the printed ID. The inspect command must report `completedAt`, no error, and a task output containing the original marker and worker PID. A non-completed job produces a failing exit code. Repeat inspection after another process restart to demonstrate persisted state. A job output should be present once, not regenerated by inspection.

`npm.cmd run worker` continuously processes the `compatibility` queue until SIGINT/SIGTERM, finishing an active cycle before closing the database. HTTP queue/run/cancel actions are denied. The CLI uses explicitly trusted local job APIs. This fixture runner is a compatibility proof, not the final scoring worker, retry policy, or crash-lease recovery design.

## Verification commands

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
```

For changed route groups, `npm.cmd exec next -- typegen` refreshes stale generated route types. Building requires the server environment variables but does not itself prove database connectivity. Database-backed admin access and the three-process fixture check must be recorded separately.

Package versions are pinned for Payload, its adapters, GraphQL, the Next environment loader, and the TypeScript worker runner. Do not use legacy peer-dependency resolution or force-install incompatible versions. Read `docs/specs/done/payload-worker-spike.md` for the completed verification record and `docs/specs/STEP_4_BACKEND_DESIGN.md` for subsequent tasks.
